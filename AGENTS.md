# TerraOrb — guide for AI coding agents

Read this first. It is the hand-over from the previous agent (Claude Code) so work can continue in another tool.

## What this is
**TerraOrb** is a website for Sri Lankan Dry Zone farmer organisations, built for the NASA Space Apps Challenge 2026
("Field Shift: Adapting Farms with NASA Data"). A farmer picks a village tank (wewa) and sees:
tank water now vs usual, a green/amber/red signal with advice (full paddy / short paddy + bethma / other field crops),
rain and heat history, a 16-day forecast, what to sow now, a 12-week sowing calendar, and a shareable summary card.
Users are farmers with little technical knowledge: **plain words first, numbers only in Advanced view.**

## Rules from the product owner (always follow)
1. **Never invent data.** If a fetch fails, stop and tell the user. Placeholder values must be marked `"demo": true` and shown as "Demo data".
2. **Keep modules separate:** data pipeline (`pipeline/`), rule engine (`pipeline/rules.py`) and the web UI (`web/`) never import each other's internals. They share only the JSON files described in `docs/schema.md`.
3. **All UI text lives in `web/si.json` and `web/en.json`** (same keys in both). No text typed into HTML/JS. The Sinhala is a draft that needs native-speaker review.
4. **Every value shown in the UI carries its data source label.** Non-NASA sources (Open-Meteo forecast and live weather; OpenStreetMap tanks) are labelled "Not NASA data" / credited.
5. Write clear, commented code a student team can follow. Explain what you did after each step.
6. Stack: Python 3 (pandas, numpy, requests, xarray, rasterio) for data; plain HTML/CSS/JS + Leaflet + Chart.js for the site (no build step); GitHub Pages hosting; scheduled GitHub Actions. No paid services. **Exception (owner decision, Nov 2026): the farm-planning end ("My farm plan", `#/farm`) has a real backend** in `backend/` (FastAPI + SQLite, phone + one-time-code login). Everything else stays static. Design contract: `docs/farm-spec.md`. Run: `backend
un.ps1` (port 8000, `MC_DEV=1` returns the login code); tests: `pytest backend/tests`.
7. Stay a website/PWA (the backend serves only the farm planner's data). Do not propose native app or store packaging for now.

Extra UI strings: `web/strings/manifest.json` lists files merged by `i18n.js`. Farmer app URL: http://localhost:8010/web/farmer.html

The **Data sources and Image credits pages (`#/data-sources`) were removed from every end** (owner decision, 15 Nov 2026); the old address redirects to the end's home. Every value still carries its source label (rule 4).

The **navigation bar** of every app is one component: markup in `tools/ends/template.html` (header, `.nav-panel`, `.site-nav`, `.nav-ind`), styles in `web/css/nav.css` (loaded last; frosted-glass sticky bar, per-end accent colours set by `body[data-end]`, a drop-down menu below 1000 px), behaviour in `web/js/nav.js` (sliding highlight, menu, scroll shadow). `js/main.js` still marks the current link with `aria-current="page"`. The landing page (`index.html`) has its own header.

The **home page of each app** shows what the app offers: shared component `web/js/home.js` + `web/css/home.css` + text `web/strings/home.*.json` (keys `hm.<end>.*`). Farmer: a services section between the tank finder and the map (`#home-services`); learn: strip + heading inside the hub; officer: hero + services around the sign-in; research: hero + services above the page; plan: a picture behind the Home title. Pictures `web/img/home/<end>-<n>.jpg` and `hero-<end>.jpg` (Google Flow; cut from sheets with `tools/make_home_images.py`); a missing picture falls back to an existing one; an optional `hero-<end>.mp4` loop plays if present.

## Run it
```powershell
# website (from the repo root; the site reads ../data)
.\.venv\Scripts\python.exe -m http.server 8010      # then open http://localhost:8010/web/
# tests
.\.venv\Scripts\python.exe -m pytest pipeline\tests
# data pipeline order
python pipeline\rain.py; python pipeline\forecast.py; python pipeline\water.py; python pipeline\rules.py; python pipeline\crops.py; python pipeline\seasonal.py; python pipeline\ndvi.py; python pipeline\advisory.py; python pipeline\finish.py
```
Windows laptop notes: Python 3.13 in `.venv`; Smart App Control blocks pandas 3.x and old rasterio (use pandas 2.2.3, rasterio 1.5.2). Use `PYTHONIOENCODING=utf-8` for console output with Sinhala.

## Ask TerraOrb (assistant)
`web/js/assistant.js` is a floating chat button on every page. It is rule-based, NOT an AI (owner decision, Nov 2026: stay rule-based, free and accurate). Every end has its own topic list with written answers (`web/js/assistant-kb.js` + `web/strings/assistant.{en,si}.json`, keys `ak.<topic>.{kw,q,a}`), matched with a spelling-tolerant ranking; when unsure it offers "Did you mean...?". Some answers fill in live numbers (tank counts, `data/validation.json`). Add a topic: write its three strings in both languages, add its id to `TOPICS` (and a page to `LINKS`), then run `node tools/test_assistant.mjs`. The older tank-question part: it matches keywords (lists in `si.json`/`en.json`, keys `assistant.kw.*`) and answers only from the tank JSON files, with the source and a link. Anything it does not understand gets a polite refusal. If you ever replace it with an LLM, keep it grounded in the data, cite sources, refuse everything else, keep the API key out of the page, and disclose the AI use.

## More NASA datasets (15 Nov 2026)
- **GLDAS-2.1 Noah soil moisture** (GES DISC, monthly, 0.25 deg): `pipeline/soil_moisture.py` (needs `EARTHDATA_TOKEN`; resumable cache in `pipeline/cache/soil_moisture/`) writes `data/farm/soil_moisture.json` (usual month values 2001-2025 + newest month, z-score). `backend/app/routes_profile.py` `_soil_moisture()` serves it as `sm_anomaly` in the farm profile; `web/js/farm/location.js` `soilCard` shows it in plain words. It is a NASA model product, NOT the SMAP measurement, and is area-level (about 25 km). Cut-offs for "drier / wetter" (+-0.5, +-1.5 sd) are drafts.
- **NASADEM elevation** (LP DAAC, 30 m): `python -m pipeline.trip.download.nasadem` downloads only the needed 1-degree tiles (cache `pipeline/cache/nasadem/`) and sets `elevation_m` / `elevation_source` in `data/trip/destinations.json` (old AWS value kept as `elevation_aws_m`). Re-run it after `python -m pipeline.trip.main --only destinations`, which would write AWS heights again.
- **NASA GIBS layer switch** on the trip Explore map and the farm zone map: `web/js/nasa-layers.js` (true colour, IMERG rain, NDVI, land surface heat; newest picture, credit "NASA GIBS"). Text keys `nl.*` in `web/strings/nasa.*.json`.
- **Phase 2 farm datasets (15 Nov 2026), five tanks only** (`phase_tanks` in `[farm]` of `pipeline/config.toml`: Nuwara Wewa + the tank nearest each farm grid cell; the farm cells are the 5 in `data/farm/index.json`). All need `EARTHDATA_TOKEN` except MODIS (ORNL web service, no login). Every file lists its source; a tank or cell with too few readings gets nothing, never a guess.
  - **SMAP L3 soil moisture** `pipeline/smap.py` -> `data/farm/smap.json` (real satellite measurement, 9 km, top 5 cm, morning pass, good-quality pixels, 2021 on; EASE-Grid 2.0 row/column computed from lat/lon). Farm profile `smap`, farmer tank page `addSmap()`.
  - **MODIS ET and land surface temperature** `pipeline/modis_water.py` -> `data/farm/modis_et_lst.json` (MOD16A2GF is gap-filled and about a year late; MOD11A2 is current). Farm profile `modis_et` / `modis_lst`. ET/PET cut-offs (0.4 / 0.7) are drafts.
  - **IMERG rain per tank** `pipeline/imerg_tanks.py` -> `data/farm/imerg_tanks.json` (reads the trip IMERG cache). Shown beside POWER on the farmer tank page (`addImerg()`); it also covers months POWER skips (Oct 2026 on).
  - **Not built:** finer (30 m) HLS/VIIRS greenness. ORNL's VIIRS NDVI stops in May 2024 and HLS NDVI needs a raster pipeline like `water.py`.
- **Officer and research (15 Nov 2026):** `pipeline/national_nasa.py [fires] [grace]` writes `data/national/fires.json` (NASA FIRMS MODIS active fires, last 7 days, public CSV; zero fires is a real answer; re-run daily) and `grace.json` (GRACE-FO JPL mascon, country-level water thickness, about 300 km, needs `EARTHDATA_TOKEN`; the 44 MB file is cached in `pipeline/cache/grace/`). `web/js/national.js` `mountNational()` shows them plus a map on `#/research` and the officer dashboard. NASA flood (MODIS Combined Flood 3-Day) and cloud fraction (MODIS Aqua) are GIBS layers in `nasa-layers.js`, so they appear on every map. A "NDVI gaps" count from the NDVI cache was tried and dropped: MOD13Q1 composites are already cloud-screened, so it showed ~0% and told nothing. FIRMS fire layers are vector tiles, so fires are drawn from the CSV instead. Not done: Learn Mode fire lesson with real recent fires.
- GPM IMERG (see the trip section) is now used for validation and a second set of models; ML estimates need the newest rain value to be recent, otherwise Settings says why none is shown.

## Known data issues (do not "fix" silently)
- NASA POWER's near-real-time GEOSIT rain from 1 Oct 2026 is about 24 times too large; `rain.py` skips it, so rain data ends 30 Sep 2026.
- POWER rain before 1997 looks too low at some places; cross-check before trusting trends.
- Several tanks share a POWER grid cell (about 50 km), so they have identical rain.

## Secrets
Earthdata login goes in environment variables only (`EARTHDATA_TOKEN`, or `EARTHDATA_USERNAME` + `EARTHDATA_PASSWORD`). Never write a token into a file, chat or commit. Tokens expire (about 60 days).
If `water.py` fails with "not recognized as being in a supported file format", run `pipeline/earthdata_check.py`.
